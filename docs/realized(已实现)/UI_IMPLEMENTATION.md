# YOCIM AGRNT UI 实现说明

> 对应 [UI_OPTIMIZATION_PLAN.md](UI_OPTIMIZATION_PLAN.md) 的 UI-0 ~ UI-6，全部阶段已完成（2026-11-15）。
> 目标：在保留既有 Agent / 工具 / 审批 / 持久化 / 安全边界的前提下，将界面重构为「左侧项目化会话 + 中间纯会话区 + 右侧工作区」的 DeepSeek Harness 风格桌面工作台。

## 1. 布局总览

```text
┌ 标题栏 36px：◫ 应用 编辑 ··············· 拖动区 ··············· ─ □ ✕ ┐
├───────────────┬──────────────────────────────────┬─────────────────────────┤
│ 会话栏 300px  │ 会话头：标题 · 项目 · 运行状态     │ 工作区面板 280px         │
│ Logo + 新会话 │                                  │ 文件 / 编辑器 / 审计 Tab │
│ 搜索 / 置顶   │ 欢迎态 或 消息流                  │                         │
│ 项目分组      │  · 用户右对齐气泡                 │ 文件树 / Monaco / 审计   │
│ 右键操作菜单  │  · 助手 Markdown                  │                         │
│               │  · 步骤时间线（内联审批）          │                         │
│               │  · 错误卡（可重试）               │                         │
│               │ 输入卡：自动增高 · 模型 · 发送/停止 │                         │
├───────────────┴──────────────────────────────────┴─────────────────────────┤

```

- 主窗口为无边框（`frame: false`），标题栏自绘并作为拖动区；窗口按钮经 IPC 控制主进程。
- 左栏折叠后不保留图标轨，由标题栏左侧的 ◫ 按钮恢复；右栏折叠后保留 46px 展开轨。
- 左右栏折叠状态写入 `localStorage`。
- 窄窗口（<1200px）时左右栏分别收窄到 270px / 250px；跨入 <1024px 自动折叠工作区（窗口最小宽度 900px）。

### 2.1 标题栏与窗口控制

- `BrowserWindow` 使用 `frame: false`；标题栏 CSS `-webkit-app-region: drag`，按钮组 `no-drag`，双击拖动区最大化/还原。
- 窗口动作为受限 IPC：`window:control`，参数仅允许 `minimize` / `maximize` / `close`，沿用 senderFrame 来源校验与 zod 校验。
- 左上角：会话栏开关（`session-collapse` / `session-expand`）、`应用` 菜单、`编辑` 菜单；右上角：最小化、最大化/还原、关闭。
- `应用` 菜单承载切换工作区、切换主题、设置；`编辑` 菜单承载新建会话、搜索会话、折叠工作区、状态栏。

### 2.2 右键菜单

- 会话行不再显示行内小按钮；右键打开菜单：重命名、导出 Markdown、置顶/取消置顶、归档/取消归档、移动到项目、删除（二次确认）。
- 项目组头右键：在项目中新建会话、重命名项目。
- 菜单通过 `Teleport` 渲染到 `body`，自动限制在视口内；`Esc` 或点击外部关闭。

## 4. 会话区与步骤时间线

### 4.1 消息模型

`ChatMessage` 在原有 `id/role/content/createdAt/streaming` 上扩展：

- `runId`：归属的运行，避免步骤挂到上一轮消息；
- `runStartedAt` / `runEndedAt`：时间线耗时；
- `steps`：工具步骤数组；
- `error`：可重试错误信息。

### 4.2 事件到步骤的映射

| Agent 事件                       | 界面处理                                                 |
| -------------------------------- | -------------------------------------------------------- |
| `run:start`                      | 记录 runId 与开始时间                                    |
| `message:delta` / `message:done` | 追加/完成助手消息（Markdown 流式渲染）                   |
| `tool:call`                      | 在当前 run 的容器消息上创建工具步骤（`running`）         |
| `approval:request`               | 按 `callId` 关联步骤，标记审批 `pending`，时间线自动展开 |
| `tool:result`                    | 更新步骤为 `done` / `failed`，写入结果摘要与结束时间     |
| `run:error`                      | 错误挂载到助手消息，渲染可重试错误卡                     |
| `run:done`                       | 关闭未决审批（按拒绝）、收尾运行中步骤、记录结束时间     |

- 同一 `callId` 重复事件只保留一个步骤（`upsertToolStep`）。
- 时间线折叠显示「已执行 N 个步骤 · Xs」「正在执行」「等待审批」；审批卡内联在步骤中。
- 错误卡显示失败原因，点击「重试」重发最后一条用户消息。
- 步骤为会话内存态；重启后恢复消息文本，工具调用记录可在审计面板查询。

## 5. Markdown 与安全

- `marked` 解析 GFM（表格、列表、代码块），`DOMPurify` 白名单净化后渲染。
- 禁用 `style/form/input/button` 标签与 `style` 属性；`script`、`onerror`、`javascript:` 等被清除。
- 链接点击由组件拦截，仅 `http/https` 通过系统浏览器新窗口打开。
- 流式渲染 60ms 节流，避免每个 token 触发 DOM 重建。
- 单测覆盖标题/列表/代码/表格、XSS 净化与安全链接保留。

## 6. 主题、快捷键与响应式

### 6.1 主题

- 默认浅色；深色为纯黑 `#000`，通过边框与浅灰面板区分层级。
- Monaco 主题跟随设置切换 `vs` / `vs-dark`。
- 关键文字色对对比度均 ≥ 4.5:1（浅色弱化文字 4.65–4.97、主色 5.13；深色弱化文字 7.46、主色 7.41）。
- 支持 `prefers-reduced-motion`，自动关闭动画与平滑滚动。

### 6.2 快捷键

| 快捷键             | 作用                     |
| ------------------ | ------------------------ |
| `Ctrl/Cmd+B`       | 折叠/展开会话栏          |
| `Ctrl/Cmd+Shift+B` | 折叠/展开工作区          |
| `Ctrl/Cmd+N`       | 新建会话（继承当前项目） |
| `Ctrl/Cmd+K`       | 展开左栏并聚焦搜索       |
| `Ctrl/Cmd+J`       | 展开/收起状态栏          |

### 6.3 响应式

- `<1200px`：会话栏 252px、工作区 240px，消息区与输入卡内边距收窄。
- `<1024px`：自动折叠工作区；顶栏隐藏工作区路径。
- 粘底滚动：距底部 80px 内跟随流式内容，用户上滑查看历史时不强制滚底。

## 8. 已知限制

- 同一时间只支持一个活动工作区，不支持多窗口并行；
- 工具步骤时间线不落库，重启后仅恢复消息文本（工具详情见审计）；
- 未实现 DSH 的插件市场、内置终端、浏览器面板与账号体系；
- Monaco 使用全量语言包，renderer 体积较大，后续可按需裁剪。
